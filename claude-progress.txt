  actually uses), it's just intentionally untracked — don't try to `git add`
  it, and don't be alarmed that `git status` doesn't mention it.
- **`autonomous/harness/`** (the cloned Anthropic autonomous-coding quickstart
  plus this repo's overrides) is gitignored and disposable — never stage
  anything from it. Its own README explains the bash policy (`ssh` reaches
  only `coolify`, no `sudo`/`docker`/system `systemctl`, no credential
  literals, no `git push --force`/`clean`/`filter-branch`, no `source`, no
  command substitution). If a command gets blocked, that's very likely the
  policy working as intended, not a bug to route around.
- **Two competing plans exist in-repo and one of them loses.**
  `docs/SUPERMCP_CONSOLIDATION_PLAN.md`, `SUPERMCP_EXECUTION_PLAN.md`,
  `SUPERMCP_VS_VESPER_TOOLS.md`, `SUPERMCP_REMOTE_STATE.md` describe folding
  Vesper's tools into the subscriber-facing `supermcp` hub on vultr.
  app_spec.txt is explicit: **do not do that**, `trading-agent` stays its own
  process/connector/host entry. When touching those docs, mark them
  superseded with a one-line pointer rather than leaving two plans pointing
  opposite ways. I have not touched them this session.
- **`docs/HANDOFF_2026-09-01.md`** (a human's handoff, not this harness's) is
  slightly stale versus app_spec.txt in one place: it recommends the
  static-bearer-only method for the claude.ai connector ("Use the
  static-bearer method, not OAuth"). app_spec.txt's M2 supersedes that —
  OAuth 2.1 with a static-bearer fallback is now the settled design (decision
  4 in app_spec §1). Follow app_spec, not the human handoff, where they
  differ.
- `supermcp` (vultr, subscriber-facing) is explicitly **out of scope** for
  this run — a different host, different audience, do not touch it, do not
  deploy to it, do not consolidate into it. It's mentioned throughout the
  docs because it shares history with this repo, not because it's in scope.
